# TF-006 — Run the Exact-Commit Automated Release Gate

**Status:** blocked

**Owner:** engineering/CI

**Depends on:** TF-005

**Blocks:** TF-007 and TF-008

**Primary evidence:** `quality/evidence/YYYY-MM-DD-tf-006-automated-gate.md`

## Task description

**Summary:** Prove the exact release-candidate SHA passes factory, content,
build, test, responsive, CI, and bundle-content checks.

**Expected change:** As QA, I want objective evidence from the candidate itself so
source inspection or results from another commit cannot be mistaken for release
quality.

**What and why:** Previous green results establish a baseline, not the final
candidate. This task reruns all automated requirements on a clean checkout and
preserves both passes and meaningful failures.

**How:** Record environment, validate content/factory files, run the large-
iPhone full suite and compact/iPad UI matrix, confirm CI, create an unsigned
engineering archive, inspect its bundle, and issue a go/no-go tied to SHA.

**Maintained automation:** Run
`EXPECTED_SHA="<EXACT_40_CHARACTER_COMMIT_SHA>" ./Scripts/release_gate.sh` from
a clean checkout, or dispatch `.github/workflows/release-gate.yml` with the
exact candidate SHA. Local artifacts are stored under
`BuildReports/release-gate/<SHA>-<UTC timestamp>/`; GitHub Actions uploads
separate preflight and engineering artifact sets. The workflow intentionally
stops before the expensive macOS matrix if named-human content sign-off fails.

## Subtasks

### TF-006.1 — Prepare isolated environment and evidence record

**Description:** Summary: make the run reproducible and free from simulator/
working-tree interference. Expected change: as an auditor, I can identify exactly
where and how tests ran. What/why: foreground theft and dirty trees previously
invalidated a run. How: clean checkout candidate SHA, record toolchain/OS, list
destinations, and create the evidence shell before commands.

**Procedure:**

1. Check out exact TF-005 SHA and require empty `git status --short`.
2. Record `git rev-parse HEAD`, `sw_vers`, `xcodebuild -version`.
3. Run `xcodebuild -showdestinations` and `xcrun simctl list devices available`.
4. Select exact compact iPhone, large iPhone, and iPad UDIDs.
5. Ensure no parallel application will steal simulator foreground.
6. Start evidence with timestamps and artifact paths.

**Done when:** Clean SHA, environment, and three exact destinations are recorded.

**Evidence:** Environment/destination table.

**Stop/escalate:** Missing destination/runtime or dirty tree blocks the run; do
not silently substitute a different matrix.

### TF-006.2 — Run content and factory gates

**Description:** Summary: validate release content and App Factory registration.
Expected change: as the product owner, I need sacred-content and factory rules to
remain enforced. What/why: compiling is insufficient if sign-off or quality
configuration regressed. How: run both content modes, JSON validation, and the
pinned central factory verifier.

**Procedure:**

```bash
python3 Scripts/validate_prayers.py
python3 Scripts/validate_prayers.py --require-signoff
python3 -m json.tool .factory/project-context.json
python3 -m json.tool quality/quality-manifest.json
```

1. Obtain authorized `ios_app_factory_rules` 0.2.0 checkout.
2. Record standard checkout SHA and exact verifier command from that standard.
3. Run registration verification against this candidate.
4. Preserve complete output.

**Done when:** Both content gates, local JSON parsing, and factory verifier pass.

**Evidence:** Commands, exit codes, counts, standard SHA, verifier output.

**Stop/escalate:** The app repo does not vendor the verifier; never invent a
script path or reuse an old pass after registration changes.

### TF-006.3 — Run the full large-iPhone suite

**Description:** Summary: run Release compilation plus all current Debug tests
on the primary iPhone destination. Expected change: as a user, I need core
logic, persistence, and primary UI to work together while production remains
free of fixtures. What/why: this is the most complete automated run. How: pass
the recorded large-iPhone UDID to the maintained harness, keep UI reset/seed
hooks confined to Debug, and retain logs.

**Procedure:**

```bash
EXPECTED_SHA="<EXACT_40_CHARACTER_COMMIT_SHA>" ./Scripts/release_gate.sh
```

1. Replace the SHA placeholder with the exact TF-005 commit.
2. Allow the script to select available destinations from `simctl` JSON and
   perform the clean Release build plus full Debug unit/UI test once on the
   selected large iPhone. Debug is required because deterministic UI reset/seed
   hooks are deliberately compiled only under `#if DEBUG`; never expose those
   fixtures by defining `DEBUG` in Release.
3. Preserve the timestamped large-iPhone logs and `.xcresult`.
4. Record test counts, skips, warnings, and duration.

**Done when:** Release build succeeds; at least the current 58 unit/integration
tests and all current UI tests pass with no unexplained skip/failure.

**Evidence:** Logs, result bundle/artifact, counts.

**Stop/escalate:** A rerun is allowed only for a documented infrastructure
invalidation; product failures require fixes/new candidate.

### TF-006.4 — Run compact-iPhone and iPad UI matrices

**Description:** Summary: verify responsive primary paths across supported form
factors. Expected change: as a compact-iPhone or iPad user, I can reach every primary
action without clipping or layout failure. What/why: the app is phone-first but
targets device families 1 and 2. How: run only the UI suite on exact additional
UDIDs using the documented command.

**Procedure:**

```bash
xcodebuild test \
  -project Anjali/Anjali.xcodeproj \
  -scheme Anjali \
  -destination "platform=iOS Simulator,id=<EXACT_UDID>" \
  -only-testing:AnjaliUITests
```

1. Run once with compact-iPhone UDID and once with iPad UDID.
2. Use isolated simulator state.
3. Retain separate result/log artifacts labeled by destination.
4. Record all current UI test counts and skips.

**Done when:** All UI tests pass independently on compact iPhone and iPad.

**Evidence:** Destination-specific logs/result bundles and counts.

**Stop/escalate:** Do not report a large-iPhone pass as responsive coverage.

### TF-006.7 — Inspect archive identity and contents

**Description:** Summary: verify what the archive would contain. Expected change: as
a privacy/content owner, I need proof that the candidate bundle matches claims.
What/why: target membership can differ from source tree. How: inspect Info.plist,
files, binary architecture/dependencies, privacy manifest, catalog, icon, and
audio absence without modifying the archive.

**Procedure:**

1. Use `plutil -p` on archived Info.plist.
2. List all archived app files with `find ... -type f | sort`.
3. Confirm bundle ID, version/build, iOS 17 minimum, device families, and
   `ITSAppUsesNonExemptEncryption = NO`.
4. Confirm app icon, `PrivacyInfo.xcprivacy`, and `prayers.json`.
5. Search for `.mp3`, `.m4a`, `.wav`, `.caf`, `.aac`; require zero.
6. Use `file`/`otool -L` to confirm arm64 and system-only dynamic dependencies.

**Done when:** Archive contents match all candidate/privacy/text-only claims.

**Evidence:** Inspection command/output summary and file counts.

**Stop/escalate:** Unexpected asset/dependency/identity returns to TF-005.

### TF-006.8 — Consolidate results and issue automated go/no-go

**Description:** Summary: turn raw artifacts into an auditable gate result.
Expected change: as TF-007/TF-008 owners, we need one decision tied to all required
checks. What/why: scattered green logs can hide a missing matrix row. How:
complete a requirement table, identify invalidated attempts, classify warnings,
and sign the decision.

**Procedure:**

1. List every required gate and result/artifact.
2. Mark missing checks `Not run`, never Pass.
3. Explain any invalidated run and why it is excluded.
4. Triage new warnings with owner/disposition.
5. Record final test counts/destinations/SHA.
6. Engineering and QA owners sign GO only if all acceptance criteria pass.
7. Update canonical backlog.

**Done when:** Complete evidence supports a named automated GO, or a clear NO
with blocking failures.
